# 小技巧&感悟

1、看一些文档时，可以把这些文档内容、或者是某一段看不懂的文字和教学，扔给ai，让它以通俗易懂的、以不同角度、详细完善地解释这一部分内容。

2、在ai coding一个软件时，最好是以软件工程流程的顺序来让ai进行开发：

**立项：**

- **目标用户**：谁用？桌面端？移动端？Web？
- **平台**：Windows / macOS / Linux / Android / iOS
- **非功能需求**：性能、离线能力、安全、隐私、合规、体积、启动速度

**需求分析：**

* **PRD（产品需求文档）**：功能描述、优先级、验收标准
* **用例图 / 流程图**：核心流程怎么走
* **API 契约**：OpenAPI / protobuf / JSON Schema
* **数据字典**：字段名、类型、含义、约束
* **错误码表**：统一错误码和提示文案
* **边界条件**：空值、超长、非法输入、并发、断网

**系统设计：**

* 数据库设计、前端界面设计、架构设计、技术栈设计
* **领域模型**：核心实体和关系（Song、Word、User、Settings）
* **数据流图 / 时序图**：请求怎么走，数据怎么流
* **架构决策**
* **数据库迁移策略**：schema 版本号、升级脚本、回滚方案
* **配置与密钥管理**：环境变量、配置文件、密钥不落库
* **安全设计**：认证、授权、输入校验、SSRF、注入、路径穿越
* **可观测性设计**：日志、指标、追踪、错误上报
* **离线/同步策略**：如果多端同步，冲突怎么解决？
* **UI/UX 设计**：线框图、组件库、主题、响应式

**开发：**

* 搭工程骨架、项目结构
* **小步提交**：每个功能一个 commit，方便回滚
* **契约优先**：先定 API，再前后端并行开发
* **代码审查**：AI 生成的代码必须人工审查
* **安全审查**：依赖漏洞、密钥泄露、注入风险
* **文档同步**：改代码时同步改文档

**测试：**

* 单元测试、性能测试、冒烟测试、集成测试、端到端测试、契约测试、安全测试、CI 自动化

**打包和部署：**

* docker（多阶段构建、镜像标签策略）、环境分离、配置与密钥、数据库迁移、回滚策略、蓝绿 / 金丝雀、健康检查、资源限制、Nginx / Ingress、自动更新

**发布与运维：**

* **监控**：Prometheus + Grafana
* **日志**：结构化日志，集中收集
* **追踪**：OpenTelemetry / Jaeger
* **告警**：Alertmanager / 钉钉 / 邮件
* **错误上报**：Sentry
* **备份与恢复**：SQLite 定期备份，测试恢复流程
* **灾难恢复**：文档化步骤

ps：以上建议偏向大项目，个人小项目可以按流程选择合适的点。

3、整个ai开发过程中，我建议按照计划、执行、验证、回顾的顺序去开发完善功能。



4、可以记电子笔记or文档，不管是正确的，还是不正确的，把所学&所见&所闻&计划&想法记录下来，并进行备份。
